# 下载性能与调优（2026-09-24）

## 与 music-video-downloader 的同源对照与修复

2026-09-24 在本机复现：旧项目的应用容器已停止，因此使用其现有 Worker 镜像和临时普通 Docker bridge 网络，只执行下载器；工具箱在实际 Worker 中通过受限出口执行。同一 B站公开链接 `https://www.bilibili.com/video/av117322685618746`，统一 1080p，原生下载器。测试脚本：`backend/tests/toolbox/compare_download_paths.py`。

| 路径 | 第 1 次 | 第 2 次 | 说明 |
|---|---:|---:|---|
| 旧项目镜像直接出网 | 3.413 秒 | 4.386 秒 | 使用旧项目 video_mp4 格式选择器 |
| 工具箱原出口 + Google DoH | 13.238 秒 | 13.208 秒 | 当前机器 TUN fake-IP 后的解析路径 |
| 工具箱临时出口 + AliDNS | 5.197 秒 | 4.634 秒 | 相同出口代理代码，只更换解析器 |

三种路径实际均选择 `30080+30280`，文件均为 17,896,663 字节，SHA-256 均为 `cf20940d646bdf96598259858fec2f81857f755e9f8f70fd84226c2717f8166a`。因此这次差距并非通过降低画质换来的。基准包括解析、下载、合并，不包括页面、队列、存储和旧项目每次进度写库；不能当作两套完整应用的端到端成绩。

解析调查：本机 `www.bilibili.com` 的 Google DoH 查询约 0.553 秒，AliDNS 约 0.041 秒；`api.bilibili.com` 分别约 0.569 / 0.028 秒，而且地址集合不同。实测支持“解析器导致的解析耗时及后续连接路径差异”为此样例主要瓶颈；尚未对每个媒体 CDN 节点单独追踪路由，不能把全部差额归因于 DNS 查询本身。

已实现按域名选择可信解析器，仅 B站 API、短链和媒体域名使用 AliDNS，其他站点保留原解析器。仅在系统 DNS 返回 TUN fake-IP 时触发，继续校验全部返回地址为公网并固定 IP 连接。域名按完整标签边界匹配，`bilibili.com.evil.example` 不会命中；缓存按域名和解析器隔离。

```dotenv
TB_EGRESS_DOH=https://dns.google/resolve
TB_EGRESS_DOMESTIC_DOH=https://dns.alidns.com/resolve
TB_EGRESS_DOMESTIC_DOMAINS=bilibili.com,bilivideo.com,bilivideo.cn,biliimg.com,hdslb.com,b23.tv
```

本机配置已生效，正式出口复测同文件 **3.206 秒**。另使用隔离测试账号完成 API → Celery → 下载/合并 → MinIO 全流程：**4.066 秒**，文件哈希相同，测试账号和产物已清理。任务时间戳只有秒精度，该次记录排队 0 秒、处理 4 秒。全流程脚本：`backend/tests/toolbox/download_pipeline.py`；9 项出口解析测试通过。

这些是同一天的少量实网样本，缓存、CDN 和带宽会波动，不承诺固定倍数，也不代表 YouTube 获得同样改善。当前改动不涉及 YouTube 登录验证。调试使用的临时代理和网络已清理，旧项目服务保持停止。

还有以下产品差异，不能直接当作这次的已测瓶颈：旧项目 video_mp4 最高 1080p，工具箱默认最高可用；旧项目有实时字节数/速度/ETA，工具箱目前进度粗略并每 4 秒刷新任务中心；工具箱 outbox 每 3 秒扫描，且 TTS 与下载共用 2 个执行槽。旧项目的 `auto` 模式还会多探测一次。两者都上传 MinIO。

回退：清空 `TB_EGRESS_DOMESTIC_DOH`，在没有正在执行的下载/搜索时重新创建 `egress` 容器；普通 `restart` 不会重新载入 `.env`。配置变化无需重建镜像；首次代码更新需先构建。

```powershell
docker compose --env-file .env -f deploy/compose.yaml up -d --no-deps egress
```

## 当前可用改动

- 搜索下载和粘贴链接均可选择最高可用画质、1080p、720p、480p 上限。按源站格式选择，不额外转码。默认最高画质不变，推荐先尝试 720p 减少文件体积。
- 受限出口对可信 DoH 返回的公网地址做有界缓存，最多 256 个条目，最长 30 秒且不超过 DNS TTL；仍验证公网地址并连接固定 IP，缓存过期后重新验证。普通内网 DNS 结果不会命中这条缓存路径。
- 支持可选 aria2 HTTP(S) 多连接下载。默认仍为 native；同一源站实测未显示明显收益，不默认增加源站连接压力。

根目录 `.env` 可设置：

```dotenv
TB_DOWNLOAD_ENGINE=aria2c
TB_DOWNLOAD_CONNECTIONS=4
```

连接数范围 1～8；4 是建议的起始测试值。运行 `scripts/start.ps1 -SkipBuild` 使环境变量生效。恢复原下载器设为 `native`。切换前等待正在执行的任务完成，避免重建 Worker 打断下载。

原来的 2 个 Worker 执行槽和批量上限 20 条保持不变。增加同时下载数量主要改善排队，不保证单个视频更快；共享带宽和源站限速可能让每个任务更慢。TTS 与媒体处理当前仍共享主执行队列。

## 本机对比证据

同一 B站公开视频，17,896,663 字节，最高可用 1920×1080。两轮交替测试：

| 下载器 | 第 1 次 | 第 2 次 |
|---|---:|---:|
| 原生 | 13.81 秒 | 14.71 秒 |
| aria2 四连接 | 13.81 秒 | 14.41 秒 |

四份输出 SHA-256 相同，多连接收益落在网络波动范围内。日志：`artifacts/download-benchmark.log`。

加入 DNS 缓存后，使用原生下载器顺序测试清晰度：

| 清晰度 | 文件大小 | 本次耗时 |
|---|---:|---:|
| 1080p | 17,896,663 字节（17.07 MiB） | 15.01 秒 |
| 720p | 8,929,706 字节（8.52 MiB） | 4.50 秒 |
| 480p | 5,333,146 字节（5.09 MiB） | 55.54 秒 |

这是一组小样本实网数据，测试顺序存在缓存预热影响，且源站/网络明显波动，不能据此承诺固定加速倍数。720p 稳定减少约一半的数据体积；480p 这次反而更慢。日志：`artifacts/quality-benchmark.log`。前端实际提交 720p、输出视频高度 720、播放与移动端布局已验证，见 `artifacts/quality-ui.json`。

更早两个任务的排队都是约 3 秒，处理分别为 46 秒/17 MB 和 6 秒/4.6 MB；当时主要耗时不在排队。持续慢的具体地址需要分开测解析、传输、合并阶段，并核对宿主机 TUN 的国内直连/国外代理路由。

## 官方选项依据

- [yt-dlp 下载选项](https://github.com/yt-dlp/yt-dlp#download-options)：外部下载器、片段并发。
- [aria2 手册](https://aria2.github.io/manual/en/html/aria2c.html)：split、max-connection-per-server、min-split-size 与代理设置。

`yt-dlp -N` 作用于支持的分片流，不等于任意 HTTP 文件多连接。当前 B站样例是独立 HTTP 音视频文件，因此使用 aria2 进行了真实对照，而不是只增大 `-N`。


## B 站免登录失败修复（2026-09-24）

现象：旧 music-video-downloader 能下载，工具箱同一链接失败并误报“需要登录”。

复现链接 `BV1X3gd6BES2`：解析成功且选中公开格式 `100026+30280`；媒体请求指向 `*.mcdn.bilivideo.cn:8082`。旧项目没有该端口限制，工具箱出口此前仅放行 80/443，CONNECT 被本地代理返回 403。日志里的“1080P 高码率需要会员”只是可选格式说明，之前分类器匹配 `use --cookies` 将它错误归为失败原因。

修复：仅为 `.mcdn.bilivideo.cn` 域名边界允许 8082，仍校验全部 DNS 地址为公网并固定目标 IP；其他域名和内网端口继续拒绝。分类器排除 B 站可选格式说明，代理连接失败与真正要求登录分别展示。

30 项定向单元测试通过，覆盖域名伪装、内网 DNS、其他端口和错误提示脱敏。四条此前失败链接在不传 Cookie 的情况下实测成功：

| 视频 | 合并文件大小（字节） |
| --- | ---: |
| BV1X3gd6BES2 | 13,567,658 |
| av117205614266117 | 66,957,779 |
| av268167852 | 23,159,571 |
| av113147792917997 | 9,243,703 |

测试中出现过 API/出口连接超时，稍后重试成功；修复不代表源站永不波动。正式任务 `363dda26-4f9a-4487-8d45-16350d67de3d` 在 15:53:16–15:53:20 执行成功，产物归原用户所有；预览端点 Range 返回 206。历史失败记录保留以追溯，新任务通过 parent_job_id 关联。

当前仍使用 `--no-playlist`，合集链接下载选中的分 P；单个产物上限仍为 100 MiB。会员限定、私有内容仍遵循源站权限。
