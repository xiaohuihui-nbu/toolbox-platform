# YouTube 免登录下载与失败提示

当前默认免登录，不读取浏览器登录态。公开且源站允许匿名访问的视频可以尝试下载；搜索成功不代表后台能匿名下载。年龄、私有权限、地区与出口网络的登录验证要求都会影响结果。

本次失败的两个连续批次包含 YouTube 视频。复现其中 `BFjrd7IdNrM` 时，源站明确返回“Sign in to confirm you’re not a bot”。补齐运行依赖后仍返回相同要求，因此不能承诺这个视频已能匿名下载；降低画质、切换列表视图或增加并发不会消除登录验证。

## 已修复

- 后端镜像补齐 Node.js 22.23.2，并显式传入 `--js-runtimes node`。
- 固定 `yt-dlp-ejs==0.8.0`，与当前 `yt-dlp==2026.8.19` 声明的依赖一致。参考 [yt-dlp 官方 EJS 配置](https://github.com/yt-dlp/yt-dlp/wiki/EJS)。
- 下载器失败时读取任务内日志末尾进行分类，仅返回预设中文提示与 error_code；不会把 Cookie、带签名 URL 或原始诊断输出发到前端。
- 区分登录验证、Cookie 失效、请求限流、视频不可用、地区限制、运行依赖缺失、格式不可用、连接超时和 403。

新失败任务的 `result.error_code` 可为 `authentication_required` 等；旧记录保留原始历史，不批量改写失败原因。任务中心详情和批量下载结果会显示新提示。

当前未提供登录态上传/账号授权界面，也没有自动绕过验证流程。若后续需要本人账号授权的下载，应单独接入按平台账号隔离的凭证管理；不要把 Cookie 内容直接粘贴到聊天或任务参数里。

验证记录：`artifacts/youtube-anonymous-check.log`（依赖已就绪，源站仍要求登录）和 `artifacts/youtube-error-check.log`（真实任务返回结构化登录验证原因）。

## 2026-09-24 再次核对与页面提示

在用户反馈仍不能免登录后，通过实际 Worker、固定出口、Node/EJS，再对之前的 `BFjrd7IdNrM` 执行一次普通 `--simulate` 解析（不使用 Cookie、不下载文件）。源站仍要求登录验证，分类结果为 `authentication_required`；本次没有获得成功下载，因此不能将 YouTube 免登录问题标为修复。之前 B站解析分流的性能改动不适用于这个登录要求。

新版下载窗口在搜索平台选择 YouTube 或粘贴 YouTube 链接时显示“免登录尝试”说明；失败结果提供原视频入口。域名匹配使用完整 hostname 边界，仅允许 HTTP(S)，拒绝包含用户名密码的外链，不把相似恶意域名当成 YouTube。浏览器登录态不会自动同步到后台；本平台仍未接入 YouTube 账号授权/凭证管理。

界面测试对登录验证失败使用受控模拟响应，覆盖失败说明和原视频链接；真实网络验证仍为上文的失败结果，二者不能混为“端到端下载成功”。
