# 全套开发方案与当前实现差异核查

核查日期：2026-09-24。项目：`E:\xhh\projects\toolbox-platform`。

> 本文保留整改前的核查快照。用户随后要求按方案实施，FastapiAdmin 基座接入已开始并完成第一批迁移；当前状态见 [基座接入记录](fastapiadmin-adoption.md)，不要将下文整改前的账户/入口描述当作最新运行状态。

## 1. 结论与核查范围

**当前项目是已能运行的工具箱 MVP，但尚未按全套方案完成 FastapiAdmin 模块化二次开发。目录基本对齐，业务基础设施与可靠性设计仍有明显缺口。** 不应把目录存在、上游代码保留、某个页面可操作，等同于方案中的模块已经实现。

基准是 [全套开发方案 v1.1](design/全套开发方案.md)。已核对它与 `E:\xhh\docs\插件式Web多功能工具箱 - 全套开发方案文档.md` 的 SHA-256，二者一致：`8FF71269CBFD3E0C39BC0A2B58C23A7A537EDB419BD39F03015D76A9030D9E14`。

本次检查包括：当前源码、依赖、迁移、Compose、已有验证记录，以及正在运行的服务、MySQL 表清单和 OpenAPI。未实施代码重构、数据库迁移、容器重启、破坏性故障注入或新一轮完整端到端测试。下文明确区分源码事实、运行状态和历史测试记录；不以健康检查推断所有工具可用。

### 已有可保留的成果

- FastAPI、Vue3、Celery、MySQL、Redis、S3/MinIO 的基本链路已建立；当前工具箱启动链路不使用 ES、Nacos。
- 工具分类、收藏、主题与深浅色、启停管理；任务查询、编辑、取消、重试、单条/批量删除和多视图已经有实现。
- 视频搜索、多链接/多选批量下载，GPT-SoVITS 适配、音色参考试听、基础离线 TTS、音频提取、JSON/Base64 工具已经接入。
- 私有文件上传下载、音视频 Range 预览、owner 隔离、任务受理幂等、事务 outbox、执行代次检查和心跳已有基础实现。
- 容器资源限制、非 root 运行、受控出口、参数列表启动子进程、Redis AOF/noeviction 已有实现。

以上表示存在实际代码和既有验证记录，不表示所有外部站点、并发和故障场景已通过验收。

## 4. FastapiAdmin 究竟复用了什么

[upstream-lock.json](../upstream-lock.json) 明确列出的运行时复用是：

1. `backend/app/core/base_model.py`：`MappedBase`，被 toolbox 模型继承。
2. `backend/app/utils/password_util.py`：`PwdUtil`，用于密码散列和校验。

原始后端代码、管理页面与前端入口备份仍保留，但“保留在仓库”不等于“被当前 Web 服务使用”。当前后端是 [application.py](../backend/app/toolbox/api/application.py) 的独立 app；当前前端 [main.ts](../frontend/web/src/main.ts) 直接 `createApp(Workspace)`，没有启动 `main.admin.ts`/`AdminApp.vue`。

因此，方案中的统一账户、角色、菜单、审计、请求/分页约定没有随这两个基础类自动获得。修正这一点需要数据和登录兼容迁移，不能只替换几个 import 或移动目录。

## 6. 任务、存储与插件的关键细节

### 6.1 任务可靠性

- 当前 job/ outbox 原子写入、领取行锁、attempt 检查是有价值的基础，不能描述成“没有幂等”。缺的是方案要求的完整版本化执行尝试与恢复闭环。
- 任务消息当前只传 job_id，恢复没有完整的 attempt 投递契约；扩展自动重试前需要把尝试代次加入消息与领取条件，避免旧消息参与新尝试。
- 失联运行任务在心跳超过约 90 秒后标为失败/取消；没有先查询外部执行状态的自动协调服务。
- 排队参数修改直接改同一 job，并更新 request_hash。用户已要求可编辑，但方案明确要求改参数创建关联的新 job。可以保留“编辑并重新提交”的体验，在底层创建新任务并关联 parent_job_id；只改展示标题则可原地更新。
- 当前手动重试创建新任务，但没有 parent/attempt 历史关联。外部提交状态为 submitting/unknown 时会拒绝直接重试，这是已有保护，仍需进一步加入对账。
- 子进程工具会创建进程组并在正常清理路径 kill 整组；尚未实现方案的先温和终止再强杀，也不能据此声称 Celery 进程被硬杀后一定无残留。

### 6.2 文件与配额

- 目前上传经 API 中转，下载/预览经鉴权代理。它与预签名 URL 方案不同，但在内网 MVP 下可以作为明确保留的取舍；不是必须为“对齐”而立刻改直传。
- 当前文件 MIME 来自文件名推断，不等于真实内容验证；缺 checksum、产物格式检查和状态转换。
- 对象键包含随机资产 ID，不会简单覆盖同名文件；但没有方案中的 attempt 分区与孤儿清理。上传 S3 与写 MySQL 不能自然构成同一个原子事务。
- 保存产物时锁用户行检查已用大小，能限制同时落库的总量竞争；任务提交时未预留预估输出容量，可能完成耗时计算后才发现空间不足。
- “2 GB”来自默认 `TB_USER_STORAGE_MB=2048` 账号配额，不是 MinIO 只有 2 GB，也不是偏离方案本身。方案中的数字是起始预算；真正缺口是管理界面配置、文件删除/回收和生命周期。调整总配额不会自动改变单文件/下载/代理限制。
- 删除任务保留产物是当前明确行为；不能通过批量删任务释放存储。补文件删除时需先补输入引用检查，避免删除运行中任务依赖。

### 6.3 自定义工具接入

当前接入方式是：增加插件目录与 Python 清单、参数 Schema、执行器；修改 `APPROVED_PLUGINS` 和固定 runner 映射；必要时增加 Vue 专用组件；重新构建部署。它是受审查的代码扩展机制，尚不是方案中的完整插件 SDK。

`ToolContext` 只有参数、owner、工作目录、取消检查、job/attempt；缺标准 assets.materialize、progress/log、provider、emit_artifact 等接口。`ToolResult` 只有单个 Path，缺 structured_data、多个 artifacts、warnings。音频处理器自行访问 DB/S3，GPT-SoVITS 适配自行修改任务结果，平台边界还需要收口。

已实现启停，但没有普通停用/紧急停止的完整区分、工具级权限、部署资源验证。方案本就不要求任意用户上传 Python 插件或在线热加载；不要把“没有在线插件市场”算作遗漏。

## 10. 建议补齐顺序与可验收交付

### 第一批：明确基座、迁移路径与执行协议

1. 以方案指定的 FastapiAdmin 统一身份和权限为目标，列出原账户映射、密码兼容、owner 外键、角色及会话切换方案。先备份并在独立数据副本迁移验证，保留现有任务/文件归属，避免删除重建用户。
2. 保留当前工作台布局、主题和已有功能，接入统一 API 客户端、鉴权、路由与状态管理。原管理页面可按模块接入，组件库调整不应破坏已经确认的外观。
3. 建立插件 manifest/SDK、Schema hash、resource profile、worker 能力与版本契约；新增工具不再修改平台业务判断，特殊 UI 走编译白名单。

验收：原用户数据不丢、普通用户/管理员权限正确、停用工具保持隐藏、错误插件版本拒绝执行、demo 插件按指南可接入。

### 第二批：任务与外部执行可靠性

1. 增补 attempts/events/outbox 租约与有限恢复；broker 发布移出持锁事务；消息与状态更新携带代次和租约条件。
2. 拆分下载、媒体 CPU、provider I/O；由能力检查确保有消费者。GPT-SoVITS 改为提交、到期查询、收集结果的短任务，加入不确定结果对账。
3. 标题原地编辑，参数变更创建关联任务；统一错误码、重试策略、取消和硬超时后的进程清理。

验收：重复投递不重复执行、旧代次不能提交、Redis/worker 故障可恢复、TTS 等待不占据下载槽位、外部请求不明时不盲目重发。

### 第三批：文件、配置与首版功能闭环

1. 增补文件状态、checksum、输入/输出引用、存储预留与结算；提供文件删除、到期清理、带安全存活窗口的孤儿对账。
2. provider 配置版本、任务配置快照、管理额度和审计；统一站内元数据搜索。
3. 完成动态表单子集/预设、标准多产物结果、音频格式转换、时间戳工具、下载探测/字幕产物和 TTS 分段重做。

验收：删除文件准确释放配额，运行输入不能被误删，任务/文件可追溯到执行及配置版本，搜索始终按 owner 限定。

### 第四批：发布与交接验收

1. 固定本次发布镜像及插件/模型来源清单，核对 API 与所有 worker 的能力版本。
2. 加入结构化任务日志、运行指标、维护调度和 worker readiness；接通构建/契约 CI。
3. 完成真实故障矩阵、备份恢复演练及资源竞争测试，再更新交付报告。

ASR、AutoClip、GPU、多步骤媒体项目、全文索引及 SSE 放在上述闭环之后按需实施；它们不能替代首版缺失的基础能力。
